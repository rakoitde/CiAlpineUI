# Part 1 — Global Standard (rakoitde CI4 Libraries)

## Identity & Language

This repository contains a **CodeIgniter 4 Composer library** developed under the
GitHub namespace **rakoitde**. All code, tests, comments, and documentation are
written in **English**.

## Package Structure

Follow the official CI4 Composer package structure:

```
your-package-name/
├── .gitattributes
├── .gitignore
├── .php-cs-fixer.dist.php
├── LICENSE                   # MIT preferred
├── README.md
├── CHANGELOG.md
├── composer.json
├── build/                    # CS-Fixer cache (git-ignored)
├── src/
│   ├── Commands/
│   ├── Config/
│   ├── Exceptions/
│   └── YourMainClass.php
└── tests/
    └── YourMainClassTest.php
```

## composer.json Conventions

- **Package name**: `rakoitde/package-name` (all lowercase, hyphenated)
- **Namespace**: `Rakoitde\PackageName\` mapped to `src/`
- **Type**: `library` | **License**: `MIT`
- **PSR-4 autoload** for `src/`, PSR-4 autoload-dev for `tests/`

```json
{
    "name": "rakoitde/your-package",
    "description": "Short description of the package",
    "type": "library",
    "license": "MIT",
    "autoload": {
```

## Coding Style

- Follow the **CI4 Coding Style Guide** via `codeigniter4/devkit` → `codeigniter/coding-standard`.
- Run `composer cs-fix` before every commit. `composer cs` for dry-run check.
- `.php-cs-fixer.dist.php` scans `src/` and `tests/` (not `app/`).

### Naming Conventions

|Element    |Convention                        |Example                    |
|-----------|----------------------------------|---------------------------|
|Classes    |PascalCase, full descriptive names|`UserAuthenticationService`|
|Methods    |camelCase, verb + noun            |`findUserByEmail()`        |
|Variables  |camelCase, descriptive            |`$userRepository`          |
|Constants  |UPPER_SNAKE_CASE                  |`MAX_RETRY_COUNT`          |
|Config keys|camelCase                         |`$defaultTimeout`          |

**Never abbreviate** unless universally understood (e.g., `Id`, `Url`, `Http`).
Prefer `$userIdentifier` over `$usrId`; prefer `findActiveUsers()` over `getActUsrs()`.

-----

## Design Patterns & Architecture

- Prefer **SOLID principles** in all class design.
- Use CI4’s **Services** pattern for dependency injection and singleton management.
- Use CI4’s **Factories** pattern where multiple instances with different configs are needed.
- Use **Interfaces** to define contracts; keep implementations swappable.
- Apply the **Repository pattern** for data access abstraction.
- Use domain-specific **Exceptions** in `src/Exceptions/`.
- Favor **composition over inheritance**.
- Apply **early return / guard clauses** to reduce nesting.

-----

## Configuration

- Config classes live in `src/Config/`.
- Use `config('YourConfig')` (short classname) so users can override via `app/Config/`.
- Users extend the package Config: `class YourConfig extends \Rakoitde\YourPackage\Config\YourConfig`.
- Use **Implicit Registrars** when hooking into known CI4 core config files.

-----

## Testing

Every class must have a corresponding test. No code is done without tests.

- Extend `CodeIgniter\Test\CIUnitTestCase` for all CI4-aware tests.
- Use `CodeIgniter\Test\DatabaseTestTrait` for DB tests.
- Use `CodeIgniter\Test\Fabricator` for test data generation.
- Use `Services::injectMock()` for service mocking.
- Test file mirrors source: `src/Foo/Bar.php` → `tests/Foo/BarTest.php`.
- Test both happy paths **and** edge/error cases.
- Coverage requires Xdebug: `XDEBUG_MODE=coverage composer test`.

-----

## Documentation

Every feature must ship with code, tests, **and** documentation.

- **README.md**: installation, quick-start, configuration reference.
- **CHANGELOG.md**: semantic versioning, every user-facing change recorded.
- **PHPDoc** on every public class, method, and property (`@param`, `@return`, `@throws`).
- Inline comments explain *why*, not *what*.
- Outdated docs are treated as bugs.

-----

## PHP Version & Standards

- Minimum PHP: **8.1** — use named arguments, enums, readonly properties, match, fibers where appropriate.
- `declare(strict_types=1);` at the top of every PHP file.
- PSR compliance: **PSR-1**, **PSR-4**, **PSR-12** (enforced by CS-Fixer).
- Use typed properties and union types consistently.

-----

## Static Analysis

- **PHPStan** at level 5; baseline in `phpstan-baseline.php`.
- **Psalm** configured via `psalm.xml`; stubs in `psalm-stubs/`.
- **Rector** for automated refactoring (dry-run only in CI).
- Run all three: `composer analyze`.

-----

## Security

- Never trust user input; validate and sanitize rigorously.
- Use CI4’s **Validation**, **Security**, and **Encryption** services.
- Never expose internal exceptions or stack traces to end users.
- Consult the [CI4 Security Guidelines](https://codeigniter4.github.io/CodeIgniter4/concepts/security.html)
  for every feature touching HTTP input or database queries.

-----

## Git & Versioning

- **Semantic Versioning**: `MAJOR.MINOR.PATCH`.
- Branches: `main` (stable), `develop` (integration), `feature/description`.
- Commit messages: English, imperative mood — `Add user authentication filter`.
- Tag releases: `git tag v1.0.0`.
- `.gitattributes`: exclude `tests/`, `build/`, `.php-cs-fixer.dist.php` from dist archives.

# Part 2 — Project-Specific: CiAlpineUI

> Generated by `/init` — describes this specific library.

## Project Overview

**CiAlpineUI** is a PHP library for CodeIgniter 4 that enables Alpine.js-powered
interactive UI components (Cells). Components extend CI4’s `Cell` class, expose
public PHP properties as Alpine.js `x-data`, and communicate with the backend via
a single POST `/component` route.

-----

## Development Commands

```bash
composer test        # Run PHPUnit tests
composer analyze     # Static analysis: phpstan, psalm, rector (dry-run)
composer cs          # Check coding style (php-cs-fixer, dry-run)
composer cs-fix      # Fix coding style
```

Run a single test file:

```bash
vendor/bin/phpunit tests/Rakoitde/CiAlpineUI/Cells/CiAlpineUiComponentTest.php
```

-----

## Architecture

### Request Flow

1. A `CiAlpineUiComponent` renders its view with `x-data` (public PHP properties
   serialized as JSON) and `x-component` (class name, optionally encrypted).
1. The bundled JS (`src/Views/CiAlpineUiJs.php`) registers an Alpine.js `$cell` magic
   that intercepts method calls and POSTs to `/component`.
1. `CiAlpineUiController` receives the POST, reconstructs the component class from
   the (decrypted) name, hydrates it with the sent state, calls the requested action
   method, and returns either rendered HTML or updated property JSON.

### Key Files

|File                                      |Purpose                                                                                                                   |
|------------------------------------------|--------------------------------------------------------------------------------------------------------------------------|
|`src/Cells/CiAlpineUiComponent.php`       |Base class all user components extend. Provides `getXTags()`, `asJson()`/`asHtml()` response mode, encrypt/decrypt helpers|
|`src/Controllers/CiAlpineUiController.php`|Handles all AJAX calls from the frontend; resolves component class, validates action, dispatches call                     |
|`src/Views/CiAlpineUiJs.php`              |The Alpine.js `$cell` magic implementation — pure JS, no build step                                                       |
|`src/Config/CiAlpineUI.php`               |Config class; `$encrypt = true` controls CI4 encrypter wrapping of the component name                                     |
|`src/Config/Routes.php`                   |Registers `POST /component` → `CiAlpineUiController`                                                                      |
|`src/Config/Registrar.php`                |Registers the `make:uicomponent` spark generator                                                                          |
|`src/Commands/UiComponentGenerator.php`   |Spark generator; creates `*Cell.php` + view from templates                                                                |

### Response Modes

A component action can switch the response mode:

- `$this->asHtml()` *(default)* — controller responds with `{ html: '...' }` and the
  JS replaces the entire root element’s `outerHTML`.
- `$this->asJson(['prop1', 'prop2'])` — controller responds with the named public
  property subset; Alpine.js merges the values into `x-data` reactively without a
  full re-render.

### Authorization Pattern

To restrict access to an action `doSomething()`, add a public method
`canAccessDoSomething(): bool` to the component. The controller calls it before
dispatching.

### Encryption

When `config('CiAlpineUI')->encrypt === true`, the component class name in the
`x-component` attribute is encrypted via CI4’s `encrypter` service and base64-encoded.
This requires `app.key` to be set in the CI4 app using this library.

- Encryption applied in: `CiAlpineUiComponent::getXComponentTag()`
- Decryption applied in: `CiAlpineUiController::getComponent()`
